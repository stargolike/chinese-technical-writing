# 常用文档结构

以下结构是起点。根据读者要完成的任务、产品复杂度和仓库现有习惯删减或调整；不要为了套模板补写不存在的功能。

## README

```markdown
# 项目名称

一句话说明项目解决什么问题。

## 功能
## 前置条件
## 安装
## 快速开始
## 配置
## 使用说明
## 故障排除
## 相关文档
## 许可证
```

短小项目可将配置、使用说明或故障排除合并；若仓库已有规范，以仓库约定为准。

## 安装或操作指南

```markdown
# 任务名称

简述目标和适用范围。

## 前置条件
## 步骤
## 验证结果
## 常见问题
```

每一步使用动作开头，说明必要输入、预期结果和分支条件。命令应放入代码块，替换值使用清晰的占位符，并解释占位符含义。

## 教程

```markdown
# 教程主题

## 学习目标
## 前置条件
## 准备工作
## 操作步骤
## 结果说明
## 下一步
```

以一个可完成的任务组织内容。复杂概念逐步引入，不假设读者已经完成文中未提及的配置。

## API 参考

按接口、资源或操作逐项说明：

- 名称、用途和适用版本。
- 调用方式、参数、类型、必填性和默认值。
- 返回值或数据结构。
- 失败条件与错误响应。
- 最小可用示例，以及必要的边界说明。

只记录可从源码、规范或可靠材料确认的行为。未知默认值不要推测。

## FAQ 与故障排除

```markdown
# 常见问题 / 故障排除

## 症状或问题
### 原因
### 解决方法
```

标题使用读者实际看到的报错或现象。先给能解决问题的操作，再补充原理；区分诊断步骤和修复步骤。

## 发布说明

```markdown
# 版本号 — 日期

## 新增
## 改进
## 修复
## 兼容性或迁移说明
```

只保留对使用者或维护者有影响的变化。版本号、日期和兼容性要求需有来源。
