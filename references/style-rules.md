# 中文技术文档风格规则

本规则把阮一峰的《中文技术文档的写作规范》归纳为写作和审校时可直接使用的准则。项目、产品或用户给出的术语表和格式要求优先。

## 标题与层级

- 标题分为四级：`#` 文档标题、`##` 主要部分、`###` 小节、`####` 次级小节。
- 不从一级标题直接跳到三级标题；避免同级标题仅有一个下级项、下级标题重复上级标题。
- 能用列表呈现的并列内容，优先使用列表，不为列表项单独增加标题。
- 四级标题只在内容较长、确有分节需要时使用。

```markdown
# 文档标题

## 安装

### 前置条件
```

## 用词与句子

- 优先选择常见、准确的现代汉语；少用口语、文言、生造词和不必要的形容词。
- 用主动表达说明谁执行什么操作。技术步骤中明确操作对象、动作和结果。
- 同一意思优先使用肯定句，避免双重否定。将“确认没有启用”改为“确认已关闭”这类直接表达。
- 使用代词时检查唯一指代。若读者可能不清楚“其”“该”“此”指什么，改写为具体名词。
- 区分“的、地、得”。删去重复修饰和不影响理解的插入语。
- 优先拆分长句。约 30 字以上应复查是否包含多个动作、条件或因果；分句过长时改用列表、编号步骤或独立句子。
- 正文语气平静、客观。惊叹号仅用于确有必要的语气，不连续使用多个感叹号。

## 段落与引用

- 每个段落只表达一个主题。先给结论或中心句，再补充原因、条件和例子。
- 段落以 4 行以内为宜，最多约 7 行。列表项也应简洁，且句式尽量平行。
- 段落之间空一行，行首不缩进。
- 引用第三方文字、数据或图片时标明出处。全文转载时，在开头醒目处说明作者和来源并链接原文。

## 中英文与空格

- 全角中文与半角英文之间留一个半角空格：`使用 Python 编写`。
- 中文与阿拉伯数字之间可以留或不留空格；同一文档只采用一种方式。百分号与数字按数字一侧处理。
- 数值与未翻译的英文单位符号之间留空格：`16 GB`、`1 h`。
- 英文字符或数字与全角标点之间不留空格：`使用 VS Code。`。
- 保留代码标识、产品名和专有名词的正式写法，如大小写、连字符和缩写。首次出现时按读者需要解释中文含义；之后统一使用一种称呼。
- 中文语境引用英文书名并使用中文译名时用书名号。中文省略语使用 `⋯⋯`，不把英文 `...` 直接当中文省略号。

## 数字和数值表达

- 使用半角数字，不使用全角数字。
- 千位以上数值使用半角逗号分组。四位数（例如 `1000`）可不分组，但全篇一致。
- 货币使用阿拉伯数字；可以在数字前写货币符号（`$1,000`），也可以在数字后写货币名称（`1,000 美元`）。英文货币名使用通行代码或 ISO 4217 代码时，不要混淆币种。
- 表示范围时使用 `～`、`—` 或“至”，按上下文选一种并保持一致。两端都写单位或百分号：`132 kg～234 kg`、`67%～89%`。
- 明确表示变化量和变化后结果：“增加了两倍”表示增量；“增加到两倍”表示结果值。减少或降低时用“降低了百分之 N”或“降低到百分之 N”，避免“降低 N 倍”。

## 标点符号

- 中文句子使用全角中文标点；完整英文句子使用半角标点。
- 中文句末用 `。`。句末括号是补充说明时，句号放在右括号之后。
- 逗号表示句内停顿；避免整段只用逗号连接。中文并列词用顿号 `、`，英文句子并列项用半角逗号 `,`。
- 引用使用成对的中文双引号 `“ ”`；引号内再引用时，内层使用 `‘ ’`。
- 中文补充说明使用全角圆括号 `（）`，括号与外文之间通常不加空格。
- 冒号用于引出解释、说明或列表；时间使用半角冒号，如 `8:00`。
- 中文省略号用六点 `⋯⋯`，不与“等”连用。避免 `。。。` 和 `...` 代替中文省略号。
- 破折号用于解释或转折，统一采用一种字形和空格方式。连接复合名词、图表编号使用半角连字符 `-`；数值范围使用波浪线 `～`、一字线 `—` 或“至”，不要与复合词连字符混用。
- 标题末尾通常不加句号、逗号、顿号、分号或冒号；引号、括号、问号等是否保留视标题语义而定。

## 文档体系与文件名

写软件手册时，按产品复杂度选择以下部分：

- 简介：说明产品及文档的用途。
- 快速上手：提供最快可行的首次使用路径。
- 入门：说明前置条件、安装和配置，并提供基础教程。
- 进阶：介绍中高级用法或开发流程。
- API 参考：逐项说明接口。
- FAQ 与附录：按需要提供术语、配方、故障处理、变更记录和反馈方式。

文件名不含空格，使用半角字符；建议使用小写字母和连字符分隔单词，如 `troubleshooting.md`、`advanced-usage.md`。`README`、`LICENSE` 等通用文件名可按项目惯例使用大写。
